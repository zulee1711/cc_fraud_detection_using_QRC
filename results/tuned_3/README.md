# tuned_3 — equal-budget tuning at L = 15: TFIM vs ESN-45

**Question.** The untuned TFIM beat the untuned equal-width ESN at L = 15 in [fraud_2](../fraud_2/README.md). Does
that edge survive when both models get the same tuning budget?

**Setup.** Same data, encoding, readout, threshold and metrics as fraud_2, at L = 15. TFIM (2 Trotter steps, 1 + 3
qubits, input reset) read out with XYZ-strings (45 observables), against an ESN with 45 units. One Optuna TPE study
per model, 100 trials, same sampler seed, both starting from the fraud_2 setting. Four hyperparameters each: TFIM
field h, evolution time, encoding scaling and readout alpha; ESN spectral radius, leak rate, input scaling and alpha.
The objective is validation customer AP (exact for TFIM), averaged over seeds 42–44. The best setting is then
evaluated once on test with seeds 42–51 (45–51 held out); TFIM is evaluated exact and at 10⁵ / 10⁴ shots per window.
Details in the docstring of [`experiments/tuned_3/run.py`](../../experiments/tuned_3/run.py).

## Reproduce

From the repository root (the references are read from `results/fraud_2`, including its untracked score files):

```bash
.venv/bin/python -m experiments.tuned_3.run tune --model tfim            # resumable, study_tfim.db
.venv/bin/python -m experiments.tuned_3.run tune --model esn             # study_esn.db
for s in $(seq 42 51); do
  .venv/bin/python -m experiments.tuned_3.run evaluate --model tfim --seed $s
  .venv/bin/python -m experiments.tuned_3.run evaluate --model esn --seed $s
done
.venv/bin/python results/tuned_3/analyze.py                               # report.md, tuning.{pdf,png}
PYTHONPATH=. .venv/bin/python results/tuned_3/operational.py              # operational.{md,csv}, operational_*.{pdf,png}
```

A local rerun of `evaluate` matches the stored ESN records to 10⁻¹¹ and the shot-sampled TFIM records to 10⁻⁴. The
exact TFIM readout is the most sensitive to floating-point differences: seed 42 gives test customer AP 0.4803 on
macOS against 0.4833 stored, with both the current and the pre-move code.

## Findings (test customer AP, mean ± std over seeds 42–51; `report.md`)

- **Tuning helps the ESN far more:** ESN-45 goes from 0.398 to 0.587 (+0.189), TFIM from 0.429 to 0.485 (+0.056).
- **Tuned TFIM is below tuned ESN-45** by 0.102 (95% CI [−0.108, −0.096]), on 0/10 seeds; the same on the held-out
  seeds 45–51 (−0.100, 0/7). At 10⁵ shots the gap grows to 0.113.
- **The untuned TFIM edge (+0.031 over ESN-45) was a tuning artefact.**
- Both tuned models beat logistic regression on the raw window (0.406); the LSTM (0.771) stays far ahead.
- **At 1 % FPR** (`operational.md`), tuned TFIM recalls 53.5 % of customer frauds against 65.7 % for tuned ESN-45,
  43.5 % for logistic and 76.2 % for the LSTM.

## Contents

| Path | What |
| --- | --- |
| `study_tfim.db`, `study_esn.db` | the Optuna studies (every trial, its parameters and per-seed validation AP) |
| `runs/<model>_tuned_s<seed>.json` | the test evaluation of the best setting, one record per readout budget |
| `report.md`, `tuning.{pdf,png}` | tuning and test tables, paired tests, tuning curves (`analyze.py`) |
| `operational.{md,csv}`, `operational_*.{pdf,png}` | metrics at the min-recall and 1 %-FPR thresholds (`operational.py`) |

Not tracked: `runs/scores/` (regenerated by `evaluate`), `operational_table_*.tex` and `logs/`.

**Note.** The run records of fraud_2 store their CLI run directories under the old path `results/2_fraud/…`;
`analyze.py` and `operational.py` resolve them under `results/fraud_2/cli_runs/`.
